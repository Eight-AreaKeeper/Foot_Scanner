# Foot Scanner 技术方案 v0.1

> 目标：用手机摄像头精准测量脚型数据，输出可直接用于球鞋定制（选码、楦型匹配、个性化鞋垫/鞋面）的参数与 3D 模型。

## 1. 结论先行

- **主方案**：多视角摄影测量（手机绕脚拍一段视频 / 20–40 张照片）+ **A4 纸作尺度参照**，云端重建 3D 网格并自动提取测量值。
- **增强方案**：iPhone Pro 系列有 LiDAR 时，同时采集深度数据用于加速和校验；没有 LiDAR 的手机走纯 RGB 路线。
- **精度目标**：脚长 / 脚宽误差 **≤ ±2 mm**（95% 样本），围度 **≤ ±4 mm**，足弓 / 脚背高度 **≤ ±3 mm**。
- **MVP**：先做「A4 纸 + 俯视 / 侧视两张照片」的 2D 快速测量（1–2 周可出原型），再迭代到完整 3D 扫描。

## 2. 采集方式对比

| 方案 | 原理 | 精度 | 设备覆盖 | 用户操作 | 评价 |
|---|---|---|---|---|---|
| A. A4 纸 + 2–3 张照片 | 纸张四角做透视校正和尺度，分割脚轮廓 | 长/宽 ±2–3 mm，无围度 | 所有手机 | 极简 | **MVP 首选**，只能给 2D 数据 |
| B. 多视角摄影测量 | SfM + MVS / 神经重建，A4 或标定垫提供尺度 | ±1.5–3 mm，含完整 3D | 所有手机 | 绕脚拍 20–40 s | **主方案** |
| C. LiDAR / ToF 深度 | ARKit Scene Depth 直接融合点云 | ±3–5 mm（LiDAR 分辨率低，细节差） | 仅 iPhone Pro / 部分安卓 | 简单 | 作为辅助校验和尺度来源 |
| D. TrueDepth 前置结构光 | 高精度近距深度 | ±1 mm 级 | 仅 iPhone 前摄 | 别扭（需他人协助或镜子） | 不作主路径 |
| E. 单图 + 统计脚型模型 | 深度网络回归参数化脚模型 | ±4–6 mm | 所有手机 | 最简 | 用作补全先验，不单独使用 |

**推荐组合**：B 为主，A 作为降级 / 快速模式，C 在可用时融合，E 的统计脚模型用于填补拍不到的区域（脚底、脚趾缝）。

## 3. 采集流程（主方案）

1. 用户把 **A4 纸平铺在硬质地面**（避开地毯），穿薄袜或赤脚，脚踩纸上，脚跟靠近纸边。
2. App 打开相机，AR 引导：屏幕显示环形进度，引导手机在 **约 40–60 cm 距离** 绕脚一圈，分高 / 低两个仰角。
3. 实时质量检查：A4 四角是否可见、模糊度、曝光、覆盖角度；不合格就地提示重拍。
4. 左右脚分别采集（左右脚常差 3–5 mm，定制必须分开）。
5. 上传关键帧（约 30–60 帧，压缩后 < 30 MB）+ IMU 数据 + 相机内参。

**需要站立负重**：脚在承重时会变长变宽，测量应在站立、两脚均匀承重下进行；坐姿采集需提示并标记。

## 4. 处理流水线

```
关键帧 → 去畸变 → A4 检测（角点 + 单应性）→ 脚部分割（SAM/轻量 UNet）
      → 位姿估计（SfM：COLMAP / ARKit 位姿作初值）
      → 稠密重建（MVS 或 3D Gaussian Splatting → 网格）
      → 尺度标定（A4 = 210×297 mm；有 LiDAR 时交叉校验）
      → 地平面拟合、去除地面与小腿以上部分
      → 统计脚模型拟合（补洞、去噪、对齐到标准坐标系）
      → 测量提取 → 输出 JSON + 网格
```

- 坐标系：Z 轴垂直地面，X 轴沿脚跟最后点到第二趾尖连线（Brannock 式脚轴），便于与鞋楦对齐。
- 尺度误差是最大误差源：A4 纸本身 ±1 mm 公差，需要用四条边共同约束；建议后续提供可打印的**带 ArUco 码的标定纸**，精度更高。

## 5. 输出的测量项

| 参数 | 定义 | 用途 |
|---|---|---|
| 脚长 | 脚跟最后点到最长脚趾尖（沿脚轴） | 鞋码 |
| 跖围宽（Ball width） | 第一、第五跖趾关节外侧最大宽度 | 楦宽 / 鞋型 |
| 跖围（Ball girth） | 经过两个跖趾关节的围长 | 合脚度核心指标 |
| 脚背高度（Instep height） | 脚长 50% 处的最高点高度 | 鞋舌、鞋面容积 |
| 脚背围（Instep girth） | 经过脚背最高点的围长 | 鞋面松紧 |
| 足弓高度 / 足弓指数 | 内侧纵弓最高点；足印面积比（Staheli / Chippaux） | 扁平足 / 高足弓判断、鞋垫 |
| 脚跟宽 | 脚跟后 1/6 处宽度 | 后跟包裹 |
| 脚踝高度 | 内外踝高度 | 高帮鞋 |
| 脚趾形态 | 埃及 / 希腊 / 方形脚 | 楦头选择 |
| 左右差 | 以上各项的左右差值 | 定制补偿 |

同时输出：**3D 网格**（OBJ / GLB，约 5–20 万面）、足底压力近似面（由网格底面推断）、置信度分数（每项一个）。

## 6. 精度验证

- **真值**：用工业结构光扫描仪（如 Artec Eva / Shining3D）或专业 Brannock 量脚器 + 卷尺，收集 30–50 双脚作为基准集。
- **指标**：每个参数的平均绝对误差（MAE）、95% 误差上界、重复测量一致性（同一人测 5 次的标准差 ≤ 1.5 mm）。
- **影响因素实验**：不同手机型号、光照、地面材质、袜子 / 赤脚、操作者熟练度。

## 7. 技术栈建议

| 层 | 选型 | 理由 |
|---|---|---|
| 移动端 | **Flutter** 跨端 UI + 原生插件（iOS：ARKit/AVFoundation；Android：ARCore/CameraX） | 一套 UI，相机 / AR 走原生保证质量 |
| 端侧推理 | Core ML / TFLite：A4 检测、脚分割、模糊检测 | 实时质量反馈 |
| 后端 | Python + FastAPI，任务队列（Celery / Redis），GPU 机器 | 重建计算重 |
| 重建 | COLMAP / OpenMVS 起步，后续评估 3D Gaussian Splatting、Neuralangelo 类方法 | 成熟可控 → 再追精度 |
| 几何处理 | Open3D、trimesh、PyMeshLab | 网格清理、测量 |
| 脚型先验 | 基于公开脚型数据集训练的 PCA 统计模型（如 FIND / Foot3D 一类数据） | 补洞、提升鲁棒性 |
| 存储 | S3 兼容对象存储 + PostgreSQL | 网格 + 测量记录 |
| 可视化 | three.js（Web 管理后台）/ SceneKit、Filament（App 内预览） | 给用户和定制师看 3D 脚型 |

如果只做 iOS，可以省掉 Flutter，直接 SwiftUI + ARKit + Object Capture（Apple 自带的摄影测量 API，端侧即可重建），开发速度最快。

## 8. MVP 范围与里程碑

**M1（约 2 周）快速 2D 测量原型**
- 拍俯视 + 内侧视两张照片，A4 校正，输出脚长、脚宽、足弓粗估、推荐鞋码（中 / 美 / 欧码）。
- 先做成 Web / Python 原型验证算法，再接入 App。

**M2（约 4–6 周）3D 扫描**
- App 引导绕拍、实时质量检查、云端重建、输出完整测量表 + 3D 预览。
- 建立 30 双脚的基准集，跑出第一版精度报告。

**M3（之后）定制对接**
- 输出与鞋楦库匹配（楦型推荐、各部位松量建议）、导出给工厂的标准格式（CSV / JSON + STL）。
- 用户账户、历史记录、左右脚对比。

## 9. 风险

- **尺度与地面**：软地面、纸张翘起会直接引入误差 → 质量检查 + ArUco 标定纸。
- **脚底不可见**：底面靠地平面 + 统计模型推断，足弓精度受限 → 可选「脚底拍照」步骤补充。
- **深色袜子 / 反光**：影响分割与匹配 → 引导赤脚或浅色袜。
- **隐私**：脚部 3D 数据属个人生物数据，需明确授权与删除机制。
